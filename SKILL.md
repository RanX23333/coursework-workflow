# Coursework Workflow

Help the student understand the assignment, produce evidence for each requested deliverable, and maintain a coherent project through revisions. Adapt to the discipline, official brief, current project state, and the student's requested level of assistance.

## Establish the current task

Identify the course, assignment, working folder, authoritative brief, rubric, existing artifacts, and requested outcome. Reuse the established project location. Inspect the current files and progress records before deciding the next step.

Respect the requested mode. A request to inspect or propose edits produces findings and a concrete proposal. An implementation request authorises the specified changes. A request for the whole assignment supports sustained progress across its stages. If the student requests one step at a time, complete that step and report its result before advancing.

Ask for missing information when it materially affects the next action. Continue independent work while waiting. Infer routine reversible implementation choices from the brief and existing project conventions.

## Work from source requirements

Read the actual assignment and rubric in full. For rotated or image-based PDF tables, inspect rendered pages and verify extraction coverage. Verify the exact feedback file before summarising its priorities.

Build a compact requirement map with these fields as relevant.

| Question | Required action or explanation | Marks | Submission artifact | Course source | Evidence | Status |
|---|---|---|---|---|---|---|
| Question identifier | What the brief asks for | Rubric value | Code, report, diagram, etc. | Lecture/lab file and page | Result or passage that fulfils it | Pending, drafted, checked, etc. |

Record page limits, local word limits, permitted methods, fixed comparison conditions, required filenames, data rules, official cover requirements, and the deadline with its timezone and source. Label student preferences and modelling choices by their origin. Resolve conflicting sources using applicable course updates and the student's clarified context, and record any remaining uncertainty accurately.

Read [the stage guide](references/stages.md) for collection, course mapping, teaching, implementation, reporting, and verification details. Load the relevant stages for the current task.

## Connect coursework to learning

Map each subquestion to concrete lecture or lab material. Explain the relevant concept, how it informs the proposed method, and the evidence needed to justify that method. Use the student's preferred teaching language and the submission language required by the brief.

For requested tutorials, organise one document per major question with its subquestions inside. Combine the original question, an accurate explanation or translation, necessary concepts, key implementation steps, and interpretation of actual results. Adjust detail to the student's feedback.

## Maintain evidence through implementation and writing

Advance in question order unless dependencies or user instructions suggest otherwise. Each completed part should connect the requirement, approach, implementation or reasoning, actual evidence, interpretation, and limitations.

Use actual runs as the source of numerical results. Trace report tables and images to the implementation that generated them. Record model selection and evaluation procedures sufficiently to explain the status of the reported evidence. For computational coursework, use the checks in the stage guide that match the actual methods.

Treat external reviews as proposals to verify against the brief, files, and outputs. Preserve a reviewer's original priority order when the user asks for that order. Distinguish mandatory requirements, confirmed errors, and optional extensions. Prefer the smallest change that resolves a confirmed issue.

Describe actual AI assistance and data-use history accurately. Apply the course's verified permissions to subsequent work and document any clarified changes in scope. Use the student's account of their contribution alongside available project evidence when preparing the declaration.

## Preserve project continuity

Use the current project structure or establish a small equivalent containing original resources, working artifacts, results, learning notes when requested, and submission files. Maintain a current entry point with paths and the next action. Add supporting records when they improve continuity or reproducibility.

Track artifact completion, successful execution, student understanding, student review, and submission as separate facts. Attribute a reported submission to the student's message or a platform receipt. Preserve useful originals and create a recoverable snapshot before consequential revisions. Use atomic replacement when files may share hard links with historical copies.

For a worked example and lessons from the source project, read [the AIP CW1 case](references/aip-cw1-case.md). Its parameters, models, filenames, limits, and visual choices are assignment-specific examples.

## Finish against the requested outcome

For a final audit, inspect the exact candidate submission, cover every requirement, run the appropriate clean reproduction, verify report-to-output consistency, inspect the final rendered document, and check archive contents and filenames. Apply checks proportionate to the artifacts and the change.

When the student requests packaging, keep the archive contents aligned with the brief. Treat uploading, publishing, and platform submission according to the user's actual authorisation. After an authorised upload, verify the receipt or submitted-file state.

Report the outcome, meaningful changes, verification evidence, final artifact locations, and any pending or unverified items. Reconcile current project records with the final artifacts so the next session can continue from the correct version.
